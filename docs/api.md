# API usage

Base path: `/api`. JSON requests and responses; browser clients use the same origin. Interactive documentation and request/response models are generated by FastAPI at `/docs`, with the schema at `/openapi.json`.

| Method | Path | Request | Result |
| --- | --- | --- | --- |
| GET | `/health` | — | `{status:"ok"}` |
| POST | `/auth/signup` | `{email,password}` | Account + session cookie |
| POST | `/auth/login` | `{email,password}` | Account + session cookie |
| GET | `/me` | Cookie | Current `{id,email}` |
| POST | `/logout` | Cookie | Revokes session |
| GET | `/projects` | Cookie | Owned project snapshots with calculated plans |
| POST | `/projects` | Project input | New project, version 1 |
| GET | `/projects/:id` | Cookie | Owned project with plan |
| PUT | `/projects/:id` | Complete project input + current version | Updated snapshot and plan |
| POST | `/projects/:id/simulate` | `{task_id,hours,version}` | Read-only impact calculation |

Project creation returns HTTP 201. Other successful endpoints return 200. Except health and signup/login, all routes require a valid session cookie.

## Project input

```json
{
  "name": "Website launch",
  "description": "Connect the work before starting.",
  "version": 1,
  "tasks": [
    {"id":"discover","title":"Discovery","hours":4,"dependencies":[]},
    {"id":"build","title":"Build","hours":6,"dependencies":["discover"]}
  ]
}
```

Names and titles: 1–80 trimmed characters. Description: at most 400 characters. Projects: up to 60 tasks. Task IDs: 1–48 ASCII letters, digits, underscores or hyphens. Estimates: integers 1–160; booleans and fractional values are rejected. Each prerequisite must be a distinct ID in the same project. Extra input properties are rejected.

Creation ignores the submitted version and starts at 1. Updates replace the full graph and require its current version. The response contains `id`, `version`, `updated` (Unix milliseconds), original task definitions and `plan`.

A plan contains `duration`, `effort`, `critical_count` and topologically ordered tasks. Planned task rows add `start`, `finish`, `slack` and `critical` to the original task fields. These are elapsed work-hour offsets, not timestamps.

## Simulation

```json
{"task_id":"discover","hours":8,"version":1}
```

The response contains the baseline duration, signed duration impact, candidate plan and saved version. It does not persist the subject estimate or change the project. A stale version returns 409.

## Errors

Errors use `{detail: string}`. Validation messages include field paths but omit submitted inputs.

- **400:** invalid email format.
- **401:** missing/expired session or invalid credentials.
- **403:** rejected origin or cross-site browser mutation.
- **404:** missing task/project or a project owned by another account.
- **409:** duplicate account email or stale project version.
- **413:** mutation request body exceeds 64 KiB.
- **422:** malformed body, invalid fields, unknown properties or invalid dependency graph.
- **429:** too many authentication attempts, with `Retry-After`.

Cookies are HttpOnly, SameSite=Strict and expire after 24 hours; `APP_ENV=production` enables Secure. Non-browser clients may omit Origin; browser mutation requests must use the configured `APP_ORIGIN`.

```sh
curl -c cookies.txt -H 'Content-Type: application/json' \
  -d '{"email":"planner@example.com","password":"a-long-unique-password"}' \
  http://localhost:8000/api/auth/signup

curl -b cookies.txt -H 'Content-Type: application/json' \
  -d '{"name":"Website launch","tasks":[]}' \
  http://localhost:8000/api/projects
```
